build!: externalize TipTap + the class utilities, drop `use-sync-external-store`, and remove the `postinstall` entirely

Three dependency-hygiene fixes, prompted by a public review of our install footprint. Two of the three were fair hits; investigating them surfaced a fourth, worse bug.

**Breaking — TipTap is no longer bundled.** `@tiptap/*` and `prosemirror-*` were declared as optional `peerDependencies` **and** bundled into a 641 KB `_chunks/tiptap.js`. Consumers who followed our own peer instructions therefore ran two ProseMirror copies. ProseMirror plugin keys are module-scoped, so the copies could not recognise each other's plugins and the editors misbehaved in ways that were near-impossible to attribute. Same failure class as the framer-motion/sonner externalization in 0.37.

If you import `RichTextEditor` or `RichChatInput`, you must now install the peers — §2a of your framework's install recipe has the exact command, or run the MCP's `preflight`. Every other component is unaffected, and the package is 641 KB smaller for everyone who never touches rich text. Twelve `@tiptap/*` packages are now declared (previously four), since the full set we import must be resolvable; two internal `prosemirror-state` imports were rerouted to `@tiptap/pm/state` so they ride the existing `@tiptap/pm` peer rather than needing their own.

**`use-sync-external-store` is gone.** It was never ours: React 18+ has `useSyncExternalStore` built in and `primitives/_internal/react-use-is-hydrated.ts` already called it directly. The dependency existed solely to feed the bundled TipTap chunk, and left with it. Our runtime dependency list is now `class-variance-authority`, `clsx`, `tailwind-merge`, `tw-animate-css`.

**`clsx` / `class-variance-authority` / `tailwind-merge` are externalized instead of bundled.** All three leak into our published type surface — 25 `.d.ts` files reference `VariantProps`, cva's inferred return type embeds `import('class-variance-authority/types').ClassProp`, and `utils.d.ts` imports `ClassValue` from clsx — so consumers must be able to resolve them for `tsc` to pass. Bundling a second copy on top of declaring them shipped the same code twice and stopped consumers' own copies (near-universal in shadcn-style projects) from deduping with ours. `tailwind-merge` moves from a devDependency to a declared dependency: it was already shipping, just hidden inside our bundle. All three are auto-installed with us — no consumer action.

**No more `postinstall`. This package now runs zero lifecycle scripts on install.** The old one printed a welcome banner and wrote a project-scoped `.mcp.json` into the consumer's repo pointing at our docs MCP. The banner was noise; silently writing a config file outside our own directory to wire someone's AI agent to our server is the exact behaviour npm's install-script blocking exists to stop, and not something a design system should do to earn a place in a dependency tree. Add the MCP deliberately with `claude mcp add --transport http shilp-sutra https://shilp-sutra.devalok.in/mcp`, or copy the bundled skill — both documented in the README. Nothing to do when upgrading; to clean up after the old behaviour, drop the `shilp-sutra` entry from `.mcp.json` and delete the `node_modules/.shilp-sutra-welcomed` / `.shilp-sutra-mcp-written` sentinels.

**Peer-map generator fix (found while doing the above).** `derive-peer-map.mjs` scanned only a component's own entry file, so peers reachable through local imports into `composed/extensions/` were never reported. Harmless while TipTap was bundled — nothing to install — but once externalized it meant a consumer could follow the recipe exactly and still hit `Cannot find module '@tiptap/core'`. The generator now walks the transitive local import graph. It also caught a pre-existing under-report unrelated to this work: `rich-chat-input` reaches `date-fns` through `_chunks/use-calendar.js` and was never listed. Under-reporting breaks builds while over-reporting only over-installs, so the graph walk deliberately errs toward listing more.
