# Phase 2b: Build Pipeline Audit

**Phase:** 2b
**Auditor:** Claude
**Date:** 2026-04-12

## Overall Rating: Strong

144 per-component entry points, well-designed chunk strategy with safe-by-default fallback, world-class "use client" annotation system. 4MB total dist (~325KB gzipped JS) is competitive for scope. Main gaps: no JS source maps shipped, stale dependencies field, monolithic framer/primitives chunks limit tree-shaking.

---

## Pipeline Flow

```
Vite 8.0.8 (Rolldown) library build
  -> 144 ESM entry points + 23 shared chunks
  -> dist/ output
       |
post-build.mjs (5 sequential steps):
  1. copy-tokens.mjs     -> copies CSS to dist/tokens/
  2. fix-dts-primitives.mjs -> copies vendored .d.ts, rewrites paths
  3. inject-use-client.mjs  -> prepends "use client" + SSR patches
  4. build-tailwind-cjs.mjs -> esbuild ESM->CJS for tailwind
  5. build-component-docs.mjs -> generates per-component docs
```

## Findings

### 1. Entry Point Strategy
**Rating:** World-Class
144 per-component entries via `collectEntries()`. 139 exports map entries with correct import/default/types conditions. Matches or exceeds Mantine/Radix.

### 2. Chunk Strategy
**Rating:** Strong
Explicit allowlist-based vendor splitting. TipTap isolation excellent (535KB only for rich text users). vendor-utils/vendor-client split correctly separates server-safe from client-only. Auto-isolation of unknown deps prevents regressions.

**Concern:** framer.js (197KB) and primitives.js (226KB) are monolithic — any animated component or any Radix-based component loads the entire chunk.

### 3. Bundle Size
**Rating:** Strong
4MB total dist, ~325KB gzipped JS. Typical consumer page: ~126KB gzipped (vendor-utils + primitives + framer + components). Competitive for a system that bundles Radix + Framer + floating-ui.

### 4. Tree-Shaking
**Rating:** Adequate
Per-component imports work correctly. Server-safe components (Stack, Text) have near-zero overhead. But shared chunks defeat granular tree-shaking: Button alone pulls 471KB raw from shared chunks. `sideEffects: ["**/primitives/**"]` prevents tree-shaking the primitives chunk (correct for safety, costly for size).
**Priority:** P2 | **Effort:** L (primitive splitting)

### 5. "use client" Correctness
**Rating:** World-Class
`@server-safe` annotation system auto-detects, validates chunk existence, patches 3 known SSR-unsafe vendor patterns. 18 source files correctly annotated. Build artifacts exempted.

### 6. SSR Safety
**Rating:** Strong
Import-level smoke test as hard publish gate. 139+ entry points tested in Node.js. Known limitation: no render-body test (documented). Smart external dep handling.
**Priority:** P2 (render-level test) | **Effort:** M

### 7. CJS/ESM Dual Package
**Rating:** Strong
ESM-only for components (correct), CJS for Tailwind only (necessary). esbuild conversion robust. No `typesVersions` for TS < 4.7 but increasingly irrelevant.

### 8. Source Maps
**Rating:** Gap
`sourcemap: false` in vite.config. No .js.map files shipped. Consumers cannot debug into DS code. DTS maps (.d.ts.map) ARE present for IDE navigation.
**Priority:** P1 | **Effort:** S

### 9. CSS Delivery
**Rating:** Strong
Clean token CSS via custom properties. Single import (`@devalok/shilp-sutra/tokens`). 59KB total CSS. No per-component CSS (Tailwind utilities generated by consumer). Load-order independent.

### 10. Dependency Externalization
**Rating:** Strong
Correct external/bundle split. React + optional peers externalized. Vendor deps properly bundled.

**Issue:** `dependencies` field has stale entries (`@floating-ui/dom`, `@tiptap/extension-list`, `@tiptap/extensions`, `prosemirror-state`) that are bundled into dist but also declared as runtime deps — causes unnecessary installs for consumers.
**Priority:** P1 | **Effort:** S

### 11. Post-Build Pipeline
**Rating:** Strong
Clean sequential orchestrator with timing and error reporting. Independent scripts. Annotation-based inject-use-client. esbuild CJS conversion.

**Risk:** Regex-based SSR patching is fragile — if upstream deps change patterns, patches silently become no-ops (SSR smoke test catches the crash).

## Top 3 Actions

1. **P1 — Ship JS source maps:** `sourcemap: true` or `sourcemap: 'hidden'`. Most impactful DX improvement.
2. **P1 — Clean dependencies field:** Move bundled deps to devDependencies. Prevents unnecessary consumer installs.
3. **P2 — Consider primitives chunk splitting:** Per-primitive chunks would reduce first-component overhead from ~60KB gz to ~10-15KB.
