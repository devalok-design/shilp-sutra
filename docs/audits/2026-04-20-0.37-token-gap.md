# 0.37 Token Gap Audit — 2026-04-20

Living doc. Every error found during the 0.37.0-next.0 post-publish investigation is logged here so we can cross-reference and surface hidden issues.

## Root cause

The TW4 migration deleted the TW3 JS preset (514 lines of `theme.extend` mapping `var(--x)` → TW utility class names). The replacement — `@theme` CSS variables — relies on TW4's auto-namespace conventions (e.g. `--color-*` → `bg-*`/`text-*`/`border-*`, `--spacing-*` → `p-*`/`w-*`/`h-*`, etc.). Any preset entry whose old name didn't map cleanly onto a TW4 namespace was silently lost — the `var()` still exists in `:root` but no utility is generated.

**Everywhere TW4 fails to emit a utility = the class silently drops in consumer builds. No error, no warning. Invisible visual regression.**

### F. Primitives namespace (intentional — do NOT elevate to @theme)

- `--pink-*`, `--purple-*`, `--red-*`, etc. — primitives stay in `:root`. No consumer class references them directly (verified via grep — only `text-red-500` in a test file, which hits TW4's built-in red palette).

## Lessons

1. **Pre-publish-audit never asserted that compiled CSS contains expected classes.** Every gate was source-only. Needs extension.
2. **Smoke consumer page used a narrow surface** (Button/Dialog/Skeleton/Tabs/Sidebar/Tooltip). Didn't render Avatar, StatusDot, SplitButton, or anything using the `w-ds-xs/sm/md/lg/xl` sizing scale.
3. **TW4's "silent drop" semantics** make gaps invisible in typecheck, lint, tests, build, AND consumer smoke. Only visual inspection in Storybook would have caught them before the 0.37.0-next.0 publish.

## G. Audit-script learnings

Initial `audit-compiled-css.mjs` had false positives for components not rendered on the smoke page — TW4 content-extraction is content-driven, so Avatar's `ring-accent-8` only emits when Avatar is imported.

**Expanded smoke page to render every primitive** so the audit exercises the full class surface. This IS the right DS discipline: a breaking-release smoke MUST render every component at least once.

| # | Finding | Action |
|---|---|---|
| G1 | Smoke page narrow → audit false-positives | Expand page.tsx to render Avatar + StatusDot + SplitButton + every size variant |
| G2 | Audit regex selector-matching brittle | Switched to literal `.${name}` substring match — reliable |
| G3 | `--spacing-ds-page-x` etc. was in wrong namespace (`ds-` prefix in media override but plain name elsewhere) | Fixed — responsive redeclarations now use `--spacing-page-x` matching the @theme declaration |
| G4 | `@devalok/shilp-sutra/ui/split-button` subpath export MISSING from package.json despite dist output existing | Fixed — added subpath export block. Risk: other subpath-less components silently unimportable too. Investigated: only split-button is a legitimate public component; data-table-* are internals, toast-registry + button-processing are private. |
| G5 | Audit false-positives from matching inside `--<name>` CSS var references (e.g. `--border-focus-width` triggered a `border-focus` hit) | Fixed in audit-compiled-css.mjs — strip `--[a-z0-9-]+` before applying class patterns. |
| G6 | `animate-shake` used in `ai/command-bar.tsx:509` but `--animate-shake` + `@keyframes shake` missing from animations.css (preset never had it — was inline in old code?) | Added both to animations.css. |

## Final resolution (2026-04-20 22:xx)

**231 / 231 DS utility classes now emit CSS in the compiled consumer output.**

Fixes applied in 0.37.0-next.1 candidate:

1. A1 + A2: `--color-neutral-{1..12}` + `--color-surface-{1,2,3,4}` aliased into @theme
2. A3: `--color-{error,success,warning,info}-6` added; `--amber-bright-6` primitive added (was missing)
3. A4 + A5: `--color-overlay` + `--color-disabled` promoted from internal :root → @theme
4. A6: `--spacing-ds-{xs,xs-plus,sm,sm-plus,md,lg,xl}` added (Avatar size fix)

9. G4: missing `./ui/split-button` subpath export

**Additional regression guards added to pre-publish-audit.mjs** (next commit): run `audit-compiled-css.mjs` after the consumer smoke completes. Any class-pattern reference in DS source that doesn't appear in the compiled consumer CSS fails publish.
