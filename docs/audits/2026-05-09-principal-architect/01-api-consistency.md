# Lens 1 — API Consistency

**Compiled:** 2026-05-09 (principal-architect audit)
**Scope:** ~118 components across `packages/core/src/{ui,composed,shell,ai}/**.tsx`. Sampled 30+ ui, 12 composed, all 5 shell, 4 ai (root + blocks).
**Rubric:** [`00-best-practices.md`](./00-best-practices.md) §§ 2 (Variant API), 3 (Controlled/uncontrolled), 4 (asChild/Slot), 5 (forwardRef/displayName), 9 (Naming).

## Executive summary

Of ~85 unique CVA-bearing components surveyed, the headline numbers look healthy: 633 `forwardRef`/`displayName` references across 165 source files, 62 components accept `asChild`, file/component naming is essentially 100% conformant. But **once you look at what's underneath the variant axes, the picture is messier than the 2026-04-06 audit memory suggests**. The canonical `variant` × `color` × `size` × `shape` taxonomy from the rubric is contradicted by Card (`color="default"` instead of `accent`), Banner (no `variant` axis at all — just color), Alert/Badge using `variant="subtle"` as a fifth member without removing the `solid|soft|outline|ghost|link` family, and Tabs introducing a non-canonical `variant="line"|"contained"` set. Size axes diverge wildly — `xs|sm|md|lg` (Input, Combobox, Select, Number-Input), `sm|md|lg` (Slider, Toggle, Switch, Checkbox, Radio, Tabs, Spinner, Progress, SegmentedControl), `xs|sm|md|lg|xl` (Avatar, AvatarGroup), and Button's 12-value soup (`xs|sm|md|lg + compact-{xs,sm,md} + icon|icon-{xs,sm,md,lg}`). The Slider-size gap flagged in 2026-04-06 IS now fixed (sm/md/lg present) — but no `xs`, contradicting the rubric. Controlled/uncontrolled story is mostly fine because of the Radix backbone, with one notable hole (`SegmentedControl` is required-controlled). `asChild` is missing from a handful of DOM-rendering components that should have it (Stack ships `as` prop instead — Mantine antipattern called out in §4). Top three systemic issues: (1) **default-color drift** — `color="default"` survives in Card/Select/Progress when v0.32 already migrated everyone else to `"accent"`; (2) **variant-axis Balkanization** — `subtle|solid|outline|soft` (Alert, Badge), `default|elevated|outline|flat` (Card), `line|contained` (Tabs), `default|solid` (SegmentedControl) all coexist with no shared mental model; (3) **size scale fragmentation**.

## Architectural observations beyond rubric

The above table already incorporates `[arch-judgment]` rows (#38–#50). Three deeper systemic notes worth surfacing here:

1. **The "v0.32 color rename" was incomplete.** The CHANGELOG and CLAUDE.md both claim `color="default"` was removed in v0.32, but Card, Select-trigger, Progress, and StatCard still ship it. Either the audit lied or three more components were silently exempted. Worth grepping pre-publish-audit hooks to ensure the rule is enforced.

2. **Radix's defaults vs ours diverge silently.** When a vendored primitive has `displayName` derived from a Radix internal (e.g. `SliderPrimitive.Root.displayName`), and we copy it into our wrapper, we inherit Radix's empty/wrong values. Cheap to fix; high DevTools value. Findings #26 and #27 capture this.

3. **No cross-component validation that color enums are aligned.** Each component declares its own subset (`Switch` has 3, `Slider` has 4, `Tabs` has 2). A type-level `SemanticColor = 'accent' | 'error' | 'success' | 'warning' | 'info' | 'neutral'` shared across the system would make drift impossible. Today there's nothing stopping a contributor adding `color="brand"` to one component and breaking parity. P2.

## Verdict

API consistency is **passable for an internal/early-adopter DS but not for a public 1.0**. The naming/structural hygiene (file kebab-case, forwardRef adoption, `*Props`/`*Variants` suffixing) is unimpressive only because it's nearly perfect — the high-leverage work was already done. What remains is the harder semantic alignment: making Card/Alert/Badge/Banner/Tabs/Toggle agree on a single `variant` × `color` × `size` grammar, eliminating `color="default"` everywhere it survived, and fixing partial-controlled holes in SegmentedControl/InlineEdit/MultiSelectPopover. None of these are individually painful — many are S-effort renames with codemod-friendly deprecation. Rolled together they're roughly 2–3 weeks for one engineer, plus stories/docs updates. **Pre-1.0 priority: findings #1–5 (color/variant rename), #15 (Stack `as` → `asChild`), #18 (SegmentedControl uncontrolled), and #26 (displayName fixes) are P1/M-or-less and unblock the most visible inconsistencies.** Findings #4 (Card variant overhaul) and #10 (Button size axis split) are P1/L and best done together as a "v0.4 API normalization" minor with a single migration guide. Slider's missing `xs` size (#8) closes the loop on the 2026-04-06 audit's last open item.
