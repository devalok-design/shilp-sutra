## Top gaps (prioritized)
- [P1] accessibility — no navigation landmark (aria-label lost on a generic div) + sub-44px chevron/dismiss (20px) targets → wrap the nav region in `<nav aria-label="Main navigation">` (or set `role`/element on the primitive), bump secondary controls to a `touch-target` util hit area, add a keyboard tab-order test for the link+chevron row.
- [P1] state-coverage (✗) — no empty/loading/disabled → add `loading?` rendering `SidebarMenuSkeleton` rows, `emptyState?: ReactNode`, and `disabled?` on `NavItem` (forward to the primitive's existing `aria-disabled` path); show each in a story.
- [P1] system-cohesion — root paints `bg-surface-raised` for shell chrome → reconcile with the `bg-surface-chrome` rule (either use the chrome tier or add to `SURFACE1_ALLOWLIST` with the "deliberate elevation (v0.19.0)" rationale).
- [P1] composability/craft — promo hand-rolls a Card + two inline SVGs bypass the Icon API → render promo as `<Card size="sm">` + `<CardAction>` (fixes same-tint surface too); swap `ChevronRight`/`CloseIcon` for `<Icon icon={IconChevronRight/IconX} size="sm" />`.
- [P2] docs-dx — doc "Defaults: None" wrong, `navItemRadius` undocumented, icon typed `ReactNode` not `IconInput` → correct all three.
- [P2] api — `footerLinks` deprecated only in prose → add `@deprecated` JSDoc + one-shot dev warning; let `promo.action` accept a `ReactNode`; disambiguate `renderItem`'s `null`.
- [P2] content-resilience — physical props → migrate chevron/badge/dismiss/border to logical (`-e`/`-s`, `border-e`) for RTL.
- [P2] visual — replace the `WithCustomLogo` hex-gradient swatch with a solid `bg-accent-9` mark or the real brand asset.

## What it does well
- **Accent rail explicitly killed** (lines 200–201 comment rejects the doubled-accent stripe) — active is tint + color + weight, the Card-bar move.
- **Restrained motion** — CSS color/transform transitions, custom `ease-productive-standard`, no bounce/overshoot; `asChild` sidesteps the primitive's unguarded active-pill spring.
- **Well-typed, slot-rich API** — `IconInput` icons, `forwardRef`+`displayName`, `renderItem`, header/preFooter/footer slots, `asChild` into framework `Link`, controlled+uncontrolled via provider.
- **Content plumbing** — `TruncatedText`, `min-w-0`, `line-clamp-2`, `99+` badge cap, `no-scrollbar` scroll region.
- **Radius/theming discipline** — role tokens, composable `navItemRadius` var, semantic tokens survive brand/dark swaps.

## Cross-DS adoption ideas
- **shadcn/Radix nav** expose a `<nav>` landmark + `aria-label` as the semantic root — adopt so AT users get a real navigation landmark (our label is currently orphaned on a div).
- **Ark UI / React Aria nav** ship first-class disabled items and loading skeletons in the collection API — wire `NavItem.disabled` and a `loading` prop to the primitive's already-present `aria-disabled` + `SidebarMenuSkeleton` (they exist; AppSidebar just doesn't surface them).
- **Linear/Vercel sidebars** treat the collapse-to-icon rail as a first-class app-layer feature; AppSidebar hardcodes `hidden md:flex` and never surfaces the primitive's `collapsible="icon"` — consider exposing it.
- **Radix Collapsible/NavigationMenu** put row actions in a purpose-built action slot — the primitive already has `SidebarMenuAction`; AppSidebar's bespoke absolutely-positioned chevron button should use it.

## Rebuild note
**Polish, not rebuild.** The composition is structurally sound — data model, slotting, and the stateless-over-`SidebarProvider` design are right. Every gap is additive/in-place: add a `<nav>` landmark + fix touch targets, wire `loading`/`emptyState`/`disabled` to primitives that already exist, move the root to the `surface-chrome` tier (or allowlist it), compose `<Card>` for the promo, swap two inline SVGs for the Icon API, migrate physical→logical props for RTL, and correct the doc drift. No API break required; `footerLinks` deprecation just needs the `@deprecated` tag it already claims in prose. Reaching 4/5 is a focused polish pass, primarily on the accessibility and state-coverage axes.
