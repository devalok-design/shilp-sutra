# ui/split-button — finish-bar audit
Finish: 3/5   Market: PARITY (lags Fluent UI SplitButton on owned menu semantics + loading)   Rebuild: polish

> Reassessed against current source (0.52.0). Substantially improved since the 2026-07-01 baseline (was 2/5): the old **P0** — `role="menu"` panel with no keyboard nav / no focus management — is **RESOLVED**. The panel now composes the DS **Popover** primitive (dialog semantics), which owns focus-in, Escape, outside-click, and focus-return. axe passes both closed and open. What remains is composability/vocabulary drift and missing state coverage, not an a11y break.

## Top gaps (prioritized)
- **[P1] api-composability** — Re-rolls Button's `variant×color` styling by hand (already diverging: Button solid has `hover:shadow-brand`, SplitButton doesn't). → Derive the half classes from `buttonVariants({variant,color,size})` (same pattern already used to borrow the `color` type), or render halves as `<Button asChild>`. Delete the five hand-maps. Single source of truth.
- **[P1] docs-dx** — Doc's Composability section falsely claims Button-vocabulary + ButtonGroup-context inheritance. → Fix the doc to match source, or (better) make it true by composing Button. Drop the stale "planned for 0.45.0" changelog line.
- **[P1] api-composability** — `variant` drops `ghost`/`link`, `size` is a parallel subset with hand-rolled height/text/padding maps. → Reuse `VariantProps<typeof buttonVariants>['variant'|'size']` or document the intentional subset explicitly.
- **[P2] accessibility** — No `touch-target` util; `xs`/`icon-*` and the narrow trigger half drop below 44px. → Add `touch-target` (or min-h/min-w) like SegmentedControl's rebuild.
- **[P2] state-coverage** — No `loading`/`aria-busy`. → Add `loading` that disables both halves and renders a Spinner in the primary, mirroring Button.
- **[P2] motion** — `active:scale-[0.97]` ungated; trigger half has no press feedback. → Gate press-scale behind `useReducedMotion()` (match Button); add matching feedback to the trigger.
- **[P2] api-composability** — No `defaultOpen`; no `asChild` on primary. → Forward `defaultOpen` to Popover; add `asChild` so the primary can be a link/Form submit.
- **[P2] visual-integrity** — `min-w-[10rem]` arbitrary + `gap-1/1.5/2` off-cadence. → Use a spacing token / `gap-ds-*` tier.
- **[P3] types** — Color maps keyed on `string` with `?? accent` fallback silently swallows a missing color. → Key on `SplitButtonColor`, drop fallbacks so a gap is a compile error.

## What it does well
- The old P0 is gone: composing Popover means focus-in, Escape, outside-click, and focus-return are correct and tested for free — a genuine architectural upgrade over the hand-rolled floating panel.
- Visually disciplined: role radius token, one edge treatment per variant, semantic-token divider tinted to match each variant/color, `overflow-hidden` attached halves — no edge-soup, no accent rail, no framework palette.
- Theming-resilient and dark-safe by construction (all step tokens, no sunken recess to invert).
- Solid, real test coverage including axe in both open and closed states.

## Cross-DS adoption ideas
- **Fluent UI `SplitButton`** owns its menu: the secondary half opens a real `role="menu"` with roving arrow-key navigation and `menuitem` semantics. We push all of that onto `dropdownContent` (stories model raw `<button>`s in a dialog popover). Consider an optional `SplitButton.Menu` compound that renders the existing `DropdownMenu` primitive so keyboard menu semantics come batteries-included, while keeping the arbitrary-content Popover path for non-menu cases.
- **Fluent + Carbon `ComboButton`** both ship a pending/loading affordance on the primary half. Adopt `loading` + `aria-busy` (Button already has the pattern).
- **shadcn/Radix pattern** builds split actions by composing `ButtonGroup` + `Button` + `DropdownMenu` — no bespoke styling map. Deriving our halves from `buttonVariants` (or `<Button asChild>`) would match that and kill the drift.
- **React Aria (Adobe)** mirrors chevron/layout via logical properties automatically for RTL rather than a manual `triggerSide` flip — worth adopting for true bidi support.

## Rebuild note
**Polish, not rebuild** — the Popover-based skeleton and a11y foundation are sound and don't need to be torn down. The substantive work is a refactor: (1) derive the two halves from `buttonVariants(...)` (or render real `<Button>`s) to collapse the duplicated styling into one source of truth and inherit the full `variant`/`size`/`ghost`/`link` taxonomy; (2) add `loading`, `defaultOpen`, `asChild`, and a `touch-target`; (3) optionally introduce a `SplitButton.Menu` compound for owned menu semantics; (4) swap the inline SVG for `<Icon icon={IconChevronDown} />`; (5) correct the doc's false Button/ButtonGroup composability claims. None of that requires a from-scratch rewrite, but the styling-duplication fix is structural enough to gate the score at 3/5 until done.
