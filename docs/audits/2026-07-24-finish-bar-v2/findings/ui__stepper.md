# ui/stepper — finish-bar audit
Finish: 3/5   Market: LAGS(Ark UI Steps / MUI Stepper)   Rebuild: polish

Multi-step progress indicator: `Stepper` (root, `role="list"`) + `Step` (derives completed/active/pending from position vs `activeStep`) + `StepperContent` (animated panel). Clean of every loud AI tell — no accent rail, no gradient text, no emoji, no raw palette, role radius tokens throughout (`rounded-pill` circle, `rounded-control` click target), semantic colors only. The gaps are finish-bar gaps, not slop: an ungated 40px content slide, active/completed visually identical, controlled-only flat-prop API, and `cloneElement` index injection that silently misindexes wrapped children. No P0 a11y or slop failure, so it clears the "shippable" bar but sits behind the best navigation peers on composition and motion polish.

## Top gaps (prioritized)
- [P1] motion — 40px `StepperContent` slide (and connector-fill transition) have no `prefers-reduced-motion` guard; `withReducedMotion` (lib/motion.ts:58) exists unused → collapse `SLIDE_OFFSET` to 0 (opacity-only crossfade) and wrap `springs.smooth` in `withReducedMotion()` when `useReducedMotion()` is true.
- [P1] state-coverage — active and completed circles are pixel-identical (`bg-accent-9`) → give `active` a distinguishing treatment (e.g. `ring-2 ring-accent-7 ring-offset-2` or a weight/elevation delta) and add an adjacent active-vs-completed story.
- [P1] api-composability — controlled-only + flat props + `cloneElement` index injection → add `defaultActiveStep` (uncontrolled), widen `description` to `ReactNode` and accept `children` as step body, and move `_index` off `cloneElement` to a context-provided order (kills the silent-misindex-on-wrapper trap + the cast).
- [P2] accessibility — no guaranteed 44px touch target and `aria-current` in only one branch → apply the `touch-target` util to the click surface and compute `aria-current` once, applied in both render branches.
- [P2] content-resilience — not RTL-safe → swap physical props for logical (`ms-*`, `origin-inline-start`) and mirror the slide/fill direction under RTL.
- [P2] docs-dx — doc `icon: ReactNode` should read `IconInput`; JSDoc icon example should use a component ref (`icon={IconShieldCheck}`) not manual sizing; rename `AllVariants` story to `States`/`Showcase`.

## What it does well
- Zero anti-slop tells — role radius tokens, semantic-only color, no accent rail/gradient/glow/emoji, one edge treatment per element.
- Correct list semantics and a real focusable `<button>` for clickable steps with proper `aria-label` and focus-visible ring+offset.
- Connector fill animates `transform: scaleX/scaleY` (not width) with transform-origin awareness — no layout thrash, clean directional fill.
- Content transition fades AND slides (proper `opacity:0`), uses a shared spring, and computes forward/back direction.
- Strong test coverage (conformance + axe + state derivation + click behavior + custom icon + vertical), plus a per-component doc that now exists.

## Cross-DS adoption ideas
- **Ark UI `Steps`** ships full compositional slots (`Steps.List/Item/Trigger/Indicator/Separator/Content`) + `defaultStep` uncontrolled + `linear` mode — we could restructure `Step` toward opt-in sub-slots and add an uncontrolled path without a hard break.
- **MUI `Stepper`** exposes per-step `error`/`optional`/`completed` and an `alternativeLabel` (label-under-circle) layout — we lack per-step error/optional entirely; both are common wizard needs.
- **Radix/Ark keyboard model** — clickable steppers should support arrow/Home/End roving-tabindex nav across the completed steps, which we don't offer.

## Rebuild note
**Polish, not rebuild.** The visual layer, tokens, a11y baseline, and test scaffold are sound and market-clean; nothing structural is wrong with the surface. The weak axis is API composability, but every fix is a non-breaking in-place extension: add `defaultActiveStep`/uncontrolled state, widen `description` to `ReactNode` + accept `children`, and relocate `_index` from `cloneElement` to context-order (removes the silent-misindex trap and the type cast) — no consumer break. Layer on the reduced-motion guard, the active/completed visual distinction, the `touch-target` util, and RTL logical properties. Estimated a focused polish pass, not a ground-up rebuild; the `cloneElement`→context-index change is the only piece that touches the component's internal contract.
