# ui/toaster — finish-bar audit
Finish: 3/5   Market: PARITY (Sonner)   Rebuild: polish

> **Scope.** `toaster.tsx` is a thin mount-once wrapper around Sonner (`unstyled: true`, `z-toast`, dev-only "no Toaster mounted" warn via `toast-registry`). The surface a consumer actually SEES is painted by `ToastContent` / `UploadToastContent` in the tightly-coupled `toast.tsx`. I audited both, since mounting `<Toaster/>` is what puts the toast surface on screen. Baseline (2026-07-01): toaster 3/5, toast 2/5.
>
> **Since baseline — genuinely fixed:** the P0 colored left accent rail is gone by default (now opt-in via `showAccent`; type is carried by the status icon + a faint `bg-error-2` tint on error), the timer-bar height is tokenized (`h-[2px]` → `h-ds-01`), and the tests now assert no-rail-by-default + `showAccent` opt-in. That closes the single worst finding and lifts the visible surface from 2/5 to shippable.
>
> **Still open from baseline (flagged twice, unfixed):** no reduced-motion guard on the framer entrances, bouncy overshoot on error/warning icons, action button re-rolls `<Button>` styling, a couple of arbitrary px values. None structural — all polish.

## Top gaps (prioritized)
- **[P1] motion** — framer entrances have no reduced-motion guard (icons scale/spring in regardless of `prefers-reduced-motion`); flagged in both prior audits, still open → set `<MotionConfig reducedMotion="user">` at the Toaster root (one line, fixes all toasts) and/or gate icon springs with `useReducedMotion()` like the 27 sibling components already do.
- **[P1] api-composability / system-cohesion** — `action`/`cancel` re-roll button styling → accept `ReactNode` or render through `<Button variant="link" size="sm">` so focus-ring/typography come from one source.
- **[P1] motion** — `springs.bouncy` (overshoot) on error/warning icons is the wrong affect → reserve bouncy for `success`, use `snappy`/`fade` for error/warning.
- **[P2] perceived-performance / motion** — no container enter/exit transition → add `initial/animate/exit` (fade + small `y`, both with opacity — no slide-no-fade) on the toast surface to replace what `unstyled` removed.
- **[P2] content-resilience** — swap physical props for logical (`origin-left`→`origin-inline-start`, `rounded-l-*`→`rounded-s-*`, `left/right`→`inset-inline`, mirror the exit `x`) for RTL.
- **[P2] docs-dx** — scrub "colored left accent bar" from `toaster.md` Changes, document `showAccent` + error tint + timer bar + the `toast.*` surface.
- **[P2] visual-integrity / magic-number** — `max-w-[60px]`, `max-h-[140px]` → nearest `ds-*` size tokens; reconcile `mt-0.5`/`py-1`/`gap-1` and spinner `h-4 w-4` onto the ds cadence / `<Spinner size>`.
- **[P2] api-composability** — `ForwardRefExoticComponent<any>` in `TOAST_TYPE_CONFIG` → type as the Tabler icon component; optionally spread rest HTML props on the Toaster wrapper.

## What it does well
- Killed the P0 accent rail cleanly — type now reads through the icon + timer color + faint error tint, and made the old look an explicit opt-in rather than a hard break.
- Genuinely thoughtful timer mechanics: hover/focus-aware self-managed dismiss that works around a real Sonner limitation (timers not resetting on in-place custom-toast updates).
- Strong a11y baseline (urgency-aware role/aria-live, sr-only upload announcements, labelled controls) and thorough tests that encode the contract.
- Correct overlay surface + single edge treatment + radius role tokens — no edge-soup, no slop tells, dark-mode safe.

## Cross-DS adoption ideas
- **Sonner** — expose its `expand` (stack-expands-on-hover) and swipe-direction config we currently bury under the wrapper; and re-add a container enter/exit so we stop under-using the engine we depend on.
- **Radix Toast** — composable `Toast.Action` / `Toast.Close` slots + a swipe-threshold API; adopt the slot model so `action`/`cancel` accept real nodes instead of `{label,onClick}`.
- **Vercel/Geist + Sonner `richColors`** — a deliberate "loud" semantic variant (full tinted surface) as a documented alternative to the icon-only default, instead of the removed rail.
- **Base UI / React Aria** — pointer-based pause (covers touch) and a documented max-stack/queue behavior for burst notifications.

## Rebuild note
**Polish, not rebuild.** The architecture is sound — wrapping Sonner is the right call, the surface tokens are correct, a11y and tests are strong, and the worst historical finding (accent rail) is already resolved. The remaining gaps are all in-place edits: one `MotionConfig reducedMotion="user"` at the Toaster root plus `useReducedMotion` gating on the icon springs (closes the repeatedly-deferred motion a11y gap), differentiate bounce by type, add a compensating container entrance, compose the action button through `<Button>`, logical-property sweep for RTL, tokenize the two arbitrary px values, and refresh the doc. No structural change warranted.
