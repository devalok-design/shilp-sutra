# Phase 0.5 — Storybook CSS Pipeline Audit

**Context:** Plan §0.5 called for a pre-migration audit of how Storybook loads our CSS, so we know which files the Phase 1-8 migration has to keep working for dev AND for consumers.

**Findings:**

## Current architecture

```
.storybook/main.ts                     Storybook config. Builder: vite via .storybook/vite.config.ts.
.storybook/preview.ts                  Imports packages/core/src/tokens/index.css + storybook.css.
.storybook/vite.config.ts              Minimal vite config, aliases + rollup warning filter only.
                                       No tailwindcss plugin here — PostCSS handles it.
storybook.css                          @import "tailwindcss";
                                       @config "./tailwind.config.ts";        ← the legacy compat directive
                                       @variant dark (&:is(.dark *));
                                       + sbdocs table restoration CSS.
packages/core/src/tokens/index.css     @imports primitives.css, semantic.css, typography.css,
                                       typography-semantic.css.
packages/core/src/tokens/*.css         :root blocks (NOT @theme yet). JS-preset consumption assumed.
postcss.config.js (repo root)          { '@tailwindcss/postcss': {}, autoprefixer: {} }.
tailwind.config.ts (repo root)         presets: [./packages/core/src/tailwind/preset]
                                       content: ['./packages/*/src/**/*.{ts,tsx}'].
packages/core/src/tailwind/preset.ts   JS preset (514 lines). Will become deprecated stub.
```

## How the chain resolves today

1. Storybook loads `.storybook/preview.ts`.
2. preview.ts imports `../packages/core/src/tokens/index.css` (our `:root` token blocks — no `@theme`, no `@utility`).
3. preview.ts also imports `../storybook.css` which:
   - `@import "tailwindcss"` — TW4 runtime CSS
   - `@config "./tailwind.config.ts"` — **LEGACY COMPAT**: pulls in our JS preset via the root `tailwind.config.ts`
   - `@variant dark (...)` — dark variant registered in CSS (already TW4-native)
4. PostCSS pipeline (`@tailwindcss/postcss` + autoprefixer) processes storybook.css, resolves the `@config`, merges preset.ts's theme extensions.
5. TW4's content scanner picks up `./packages/*/src/**/*.{ts,tsx}` per `tailwind.config.ts`.
6. Generated CSS injected into Storybook preview iframe.

## Bugs / observations in current setup

1. **`storybook.css` has `@config` + `@variant` in the same file.** Mixed TW3-compat + TW4-native. Works today because TW4 accepts both, but it's the exact "half-migrated" state we're getting out of.
2. **preview.ts imports `tokens/index.css` directly**, bypassing the `@import "@devalok/shilp-sutra/css"` path that real consumers will use in 0.37. Means Storybook loads the tokens via source-relative path; consumers via `exports` field of the published package. Post-migration these become the same file, just referenced differently. No action needed here.
3. **`tailwind.config.ts` references `./packages/core/src/tailwind/preset`.** Will go stale the moment we stub the preset. Migration needs to update this file too.
4. **No `@source` directive** — Storybook currently relies on the JS preset's content path inheritance. Once we switch to CSS-first, storybook.css needs `@source "../packages/*/src/**/*.{ts,tsx}"`.

## Migration implications for Phase 4

When Phase 4 switches `packages/core/src/tokens/shilp-sutra.css` to the TW4-native consumer entry:

1. **preview.ts must swap imports**:
   ```ts
   // Before
   import '../packages/core/src/tokens/index.css'
   import '../storybook.css'
   // After
   import '../storybook.css'   // storybook-specific: sbdocs table fix, @source decl
   // The shilp-sutra tokens get imported via storybook.css's @import
   ```
2. **storybook.css rewrites** to:
   ```css
   @import "tailwindcss";
   @import "../packages/core/src/tokens/shilp-sutra.css";
   @source "../packages/*/src/**/*.{ts,tsx}";

   /* storybook-specific (sbdocs tables, etc.) stays */
   ```
   Drops `@config` and `@variant dark` — both inherited from shilp-sutra.css now.
3. **`tailwind.config.ts` at repo root**:
   - Can be deleted entirely if storybook + consumer are the only users.
   - Check any other consumer of this file first (CI scripts, Playground app, etc.).
4. **`postcss.config.js` stays.** `@tailwindcss/postcss` is the correct TW4 processor.

## Risks

1. **Hot-reload during migration.** If Phase 1 renames `--font-size-*` → `--text-ds-*` but Phase 2 hasn't moved utilities yet, `text-heading-xl` will temporarily reference undefined vars. Mitigate: stage Phase 1 + 2 in one commit, or test Storybook HMR after each sub-phase.
2. **storybook-dark-mode addon** — uses `document.documentElement.classList.toggle('dark')`. Our `@custom-variant dark (&:where(.dark *))` matches descendants of `.dark`. The addon puts `.dark` on `<html>`, preview content is always a descendant → correct. Verified no conflict.
3. **`@tailwindcss/vite` plugin is a devDep** but not wired into `.storybook/vite.config.ts`. Storybook uses PostCSS instead. No action — PostCSS path works, vite plugin is extra.

## Decisions

1. **Phase 4 migration of Storybook is atomic** with the main tokens migration. Single commit: new `shilp-sutra.css`, updated `storybook.css`, updated `preview.ts`. Don't half-migrate.
2. **Delete root `tailwind.config.ts` in Phase 4** after verifying no other consumer. Grep for `tailwind.config` references across the monorepo first.
3. **storybook.css stays** as the file for storybook-specific style tweaks (sbdocs tables, manager chrome). It just stops being the TW entry point.

## Acceptance for Phase 4 Storybook part

- `pnpm dev` boots Storybook without errors.
- Button story renders with correct bg/text colors (tokens resolving).
- Dark mode toolbar toggle changes tokens (verified on Card + Input + Alert).
- DevTools → Network: no 404s on CSS imports.
- Generated CSS in preview iframe contains `text-heading-xl`, `bg-surface-raised`, etc. — i.e. the `@utility` and `@theme` work shipped correctly.
