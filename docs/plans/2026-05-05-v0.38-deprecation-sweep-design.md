# 0.38.0 — Deprecation Sweep + Dependency Bump

**Date:** 2026-05-05
**Author:** Mudit Lal (with Claude Code)
**Status:** Approved

## Summary

0.38.0 is a tightly-scoped breaking minor: remove every API marked
`@deprecated` in 0.36 / 0.37, and refresh two dev dependencies. No new
components, no new variants, no new tokens.

The release exists to clear technical debt that has accumulated as a
visible-but-tolerated tax in the source tree. Each of the targets below has
been advertised in TS warnings, runtime stderr, or both for at least one
minor version, so consumer-facing surprise is low.

## Removals (breaking)

| # | Surface                                | File                                                  | Replacement                          |
|---|----------------------------------------|-------------------------------------------------------|--------------------------------------|
| 1 | `./tailwind` and `./tailwind/preset` exports | `packages/core/src/tailwind/preset.ts` + package.json `exports` + post-build CJS conversion | `@import "@devalok/shilp-sutra/css"` |
| 2 | `Alert.variant="filled"` alias         | `packages/core/src/ui/alert.tsx`                      | `variant="solid"`                    |
| 3 | `SegmentedControl.variant="accent"` alias | `packages/core/src/ui/segmented-control.tsx`        | `variant="solid"`                    |
| 4 | `ResponsiveOverlay` component          | `packages/core/src/composed/responsive-overlay.tsx` + composed index | `Dialog` / `Sheet` directly (both auto-adapt to mobile) |
| 5 | `hooks/use-toast` re-export module     | `packages/core/src/hooks/use-toast.ts` + package.json `exports` + hooks barrel | `import { toast } from '@devalok/shilp-sutra'` |
| 6 | `inputVariants` export alias           | `packages/core/src/ui/input.tsx` + ui barrel          | `inputWrapperVariants`               |
| 7 | `Banner.action` (singular) prop        | `packages/core/src/ui/banner.tsx`                     | `actions={[…]}`                      |
| 8 | `Input.startIcon` / `Input.endIcon` props | `packages/core/src/ui/input.tsx`                   | `startSection` / `endSection`        |

## Dependency bumps (non-breaking)

- TipTap 3.22.4 → 3.22.5 across all 10 `@tiptap/*` packages (devDeps,
  bundled into `_chunks/tiptap.js`).
- `@tabler/icons-react` 3.41.1 → 3.42.0 (devDep; consumer-side peer is
  `^3.0.0`, no consumer action).

## Migration story

- New `## v0.38.0 — Deprecation sweep` section in repo-root `MIGRATION.md`
  with before/after snippets for every removal. Most are 1-line
  find/replace; the `./tailwind` removal already has a full guide in the
  v0.37 section, so 0.38 just links back.
- Two changesets: one `major`-bump for the API removals (in 0.x changesets'
  `major` produces a minor bump — this is the right semantic), one `patch`
  for the dep bumps.
- Consumer impact triage: before publishing, grep the Karm app repo for
  any stale usage of the removed surfaces. If hits found, file a DS Notice
  via `/send-karm-notice` ahead of the publish.

## Process

- Single feature branch: `chore/v0.38-deprecation-sweep`.
- Order of work (lowest blast radius first):
  1. Dependency bumps (TipTap + Tabler) — separate commit.
  2. Removals one commit each, alphabetical by surface to make `git bisect`
     ergonomic if a regression slips through.
  3. Each removal commit must update tests, Storybook stories,
     `llms.txt` / `llms-full.txt`, and `docs/components/**/*.md` in the
     same commit. The CVA-vs-doc audit gate fails otherwise.
  4. `MIGRATION.md` update.
  5. Two changeset files (`.changeset/v0.38-removals.md`,
     `.changeset/v0.38-dep-bumps.md`).
- Pre-publish-audit gates already cover most of this (tests, lint, types,
  bundle, surface, CVA/doc, SSR smoke, TW4 hygiene). Run
  `node scripts/pre-publish-audit.mjs` locally before opening the PR —
  if it passes, CI will too.
- PR opens against `main`. Changesets/action will produce the version PR;
  release.yml publishes on merge.

## Out of scope

- New components or variants.
- Token additions or renames.
- Storybook 10 features beyond what's already in.
- Karm notice (separate user-triggered action via `/send-karm-notice` once
  the sweep lands).

## Acceptance criteria

- `pnpm typecheck && pnpm lint && pnpm test && pnpm build` all green.
- `node scripts/pre-publish-audit.mjs` passes locally.
- `MIGRATION.md` has a v0.38 section with one entry per removal.
- `llms.txt` and `llms-full.txt` have zero references to removed APIs
  (search by name).
- `packages/core/CHANGELOG.md` after `pnpm changeset version`:
  - bumps to `0.38.0`
  - lists every removal in the breaking section
  - lists the dep bumps in the patch section
- Karm app repo: zero compile errors against the dist tarball pre-publish
  (dry run via `pnpm pack` + manual install).
