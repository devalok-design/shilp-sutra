## Phase 2 — Truncation (its own PR)

**What:** Long text (filenames, names, emails, menu items) currently either overflows, wraps badly, or gets cut off with no way to read the full thing. We fix it system-wide with **one new building block**.

- Build **`<TruncatedText>`** — wraps any text and: cuts it cleanly with "…", supports "cut in the middle" for filenames/emails (so you still see `.pdf` and the domain), and **shows the full text in a tooltip only when it's actually cut off**. Full text always stays readable by screen-readers.
- Apply it at ~25 spots (sidebar items, file names, notifications, command palette, menus, breadcrumbs, tabs).
- Fix 7 spots where "cut with …" silently does nothing because of a CSS gotcha (`min-w-0`).
- **Never cut:** page titles, toasts, error messages, numbers (a cut number is a wrong number).

## Phase 3 — Card "slot" features (additive, the polish from the artifact)

**What:** Make the card a flexible tile with predictable corners, so people can shape it to any use.

- **`deltaPlacement="inline"`** on StatCard — let the "▲ 12%" sit to the right of the big number (same baseline), wrapping below if cramped; the number is never cut.
- **Corner slots** — a top-right and bottom-right slot that accept anything (icon, badge, "Live" dot, sparkline, trend pill, menu button, "View →" link, progress ring).
- **Accent badge slot** — the card's accent now rides a badge in the top-right (matches StatCard's icon position) instead of the removed colored rail.
- **Button-edge auto-align** — ghost/text buttons at a card edge get nudged so their label lines up with the content (the optical tuck), applied automatically by the card's footer/header.
